# Contributing to the Art Store

Thank you for your interest in contributing to the Art Store! This document outlines the guidelines and workflow for contributing to the repository.

## Getting Started

1. **Fork the Repository:** Fork this repository to your own GitHub account.
2. **Clone:** Clone the forked repository to your local machine.
3. **Install Dependencies:** Run `npm install`.
4. **Environment Variables:** Copy `.env.example` to `.env` and fill in `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.
5. **Start Dev Server:** Run `npm run dev`.

## Branching Conventions

When creating a new branch, please follow this naming convention:
- `topic/short-description` (e.g., `feature/admin-refactor` or `bugfix/gallery-loading`)

Keep your changes focused and small to ensure an easier review process.

## Development Workflow

Before submitting a Pull Request, you **must** ensure your code passes all quality checks:

```bash
# 1. Check and fix formatting
npm run format

# 2. Check for linting errors
npm run lint

# 3. Verify TypeScript definitions (Strict Mode)
npx tsc --noEmit

# 4. Ensure the application builds perfectly
npm run build:dev
```

### Important Notes on Generated Files
- The `src/routeTree.gen.ts` file is generated automatically by TanStack Router. **Do not edit this file manually.**
- Avoid unnecessary edits to `package-lock.json` unless you are explicitly updating or adding a dependency.

## Pull Request Guidelines

1. Open a PR against the `main` branch.
2. Provide a clear, descriptive title.
3. Describe exactly what changed and why.
4. If your changes affect the UI, **include screenshots** in the PR description.
5. Mention which files were touched and note if any generated files (like `routeTree.gen.ts`) had to be modified and why.
6. A GitHub Actions CI pipeline will automatically run against your PR to verify formatting, linting, and build stability.

We look forward to reviewing your contributions!
